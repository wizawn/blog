# 言零博客（`blog.caowo.de`）真人写作与去 AI 味规范（v3）

本站唯一文风标杆是站内置顶原文 `source/posts/google-ai-ultra-trial/index.md`（《用 Frida 借 Google One 进程调 BillingClient，开出 Google Ultra 的 $0 试用》）。

很多大模型以为“去 AI 味”就是删掉几个连接词，结果写出来的东西要么变成干巴巴的官方说明书，要么变成满嘴“兄弟们、炸裂了”的营销号，跟标杆文摆在一起完全像两个人写的。要写出真正一致的**活人感、真人感**，动笔前必须先把下面这套思维方式、开篇引流规矩和句法肌肉记忆吃透：

- **写前必读**：先翻一遍 [style-benchmark.md](references/style-benchmark.md)（标杆文呼吸节奏与 12 组人机腔改写对照）和 [genre-templates.md](references/genre-templates.md)（本站 5 类题材的统一声线骨架）。
- **写后必跑**：落笔保存后必须运行 `python3 ~/.gemini/config/skills/yanling-blog-style/scripts/check_ai_smell.py <文件路径>`，确认输出 **`OK (0 issues)`** 才能定稿。

## 一、真人和人机的六条分水岭（解决“风格迥异、人机感强”）

同样讲一个技术链路，大模型默认生成的“人机文”和言零博客的“活人笔记”差在下面六件事上：

1. **人机爱装全知上帝，真人只记肉身折腾现场**
   - 人机文永远站在事后诸葛亮的高度，一上来就列 `三大核心原理`、`四步标准方案`，仿佛作者从没敲错过一个字符。
   - 真人写博客是在记自己怎么跟系统斗智斗勇的：怕手滑扣走 $199.99 所以卡里特意只放 3 美元；先试 Magisk 装不上才退而求其次换 Frida；满怀希望拿 `g1.ai.pro` 去查却吃了一鼻子灰；甚至连“写了个回查脚本结果日志打出 `Connected` 后一直没输出，最后干脆肉眼看弹窗算了”这种半途而废的小尾巴也坦坦荡荡写出来。**敢写弯路、敢留不完美的真实细节，活人味当场就立住了。**

2. **人机靠加粗和破折号吼重点，真人靠反引号和具体数字说话**
   - 对标杆原文做全量统计：`163` 行正文里，破折号 `——` 是 **`0` 个**，`- **小标题**：说明` 列表是 **`0` 个**，自然段里的 `**加粗**` 也是 **`0` 个**！
   - 真人默认读者看得懂技术，从来不拿荧光笔满屏乱涂。想强调重点，直接摆出精确的函数名 `` `getPriceAmountMicros()` ``、商品串 `` `g1.play.ai.pro` ``、金额 `$199.99`、日志字节数 `body_bytes_sent = 33`，信息密度一上去，根本不需要加粗造势。

3. **人机逢三必列提纲表，真人用口语把坑串成连贯段落**
   - 大模型一遇到三个以上的注意点、排错项或步骤，肌肉反射就是切碎成 `1. **xxx**：... 2. **xxx**：...`，整页读起来像 PPT 讲义。
   - 真人碰到一连串细碎坑点时，会顺着时间或因果用口语过渡句一段段往下推：`"第一个低级坑是命令行习惯……"` -> `"进到脚本里之后，最折腾人的是……"` -> `"然后是……"` -> `"说起来为什么非得用 Handler？因为……"` -> `"还有一个界面操作上的小插曲：……"`。全文列表行占比严禁超过正文的 `35%`。

4. **人机一口气写八十字翻译腔，真人长短句交替留气口**
   - 别写那种夹着两层定语从句、中间还塞个 `（注：……）` 的公文长句。讲完一段密集的协议或代码逻辑之后，冷不丁接一句十来个字的独立短句换口气（如 `"这就有点不对劲了。"`、`"但真正把这几步串起来跑通，中间踩的细碎坑一点不少。"`、`"那两小时的空白期，人家根本没在死磕密码学，而是转头把密钥明文读走了。"`——注意别撞 `不是…而是`，直接写成 `"那两小时的空白期，人家压根没去死磕密码学，转头直接把密钥明文读走了。"`）。

5. **人机开头铺垫时代背景，真人第一句就甩出反常现象和引流词**
   - 严禁写 `"随着大模型技术的普及……"`、`"在日常运维工作中，我们经常会遇到……"`、`"本文将从以下三个维度……"`。
   - 第一段前三句话直接把读者搜进来的核心词、软件版本、档位价格或离谱报错拍在桌面上，顺嘴带一句记笔记的由头（如 `"顺手把整个摸索过程和踩的坑记一笔，免得过阵子自己都忘了当初怎么绕出来的。"`）。

6. **人机结尾必升华说教，真人把活干完扭头就走**
   - 严禁写 `## 总结`、`## 结语`、`## 写在最后`，更严禁写 `"安全是一场永无止境的博弈"`、`"希望本文能对大家有所帮助，欢迎评论区交流"`。
   - 最后一个技术小节把止血命令、防自动续费提醒或配置核对项交代完，直接收笔。需要交代脱敏时，在文末 `---` 底下轻轻放一行斜体 `*文里略去了具体账号和卡信息。*` 即可。

## 二、开篇引流词与顶部导流卡片双保险（硬性规则，绝不可丢！）

更新或新建本站文章时，必须同时守住**“搜索引流词”**与**“站点顶部导流区”**两道流量入口：

1. **标题与首段前 150 字必须稳稳咬住核心搜索引流词**
   - 读者是从搜索引擎或技术社区搜具体关键词进来的（例如 `ChatGPT Plus`、`ChatGPT Pro 20x`、`Claude Max`、`Claude 焚决`、`ChatGPT 提链`、`Codex Reconnecting 5 次`、`Codex 292 防降智 Overload`、`GPT-5.4 Thinking 降智 Juice 值`、`gpt-5.6-sol-wm`、`OpenClaw 部署`、`MOSS-TTSD`、`Windsurf API 反代`、具体 `CVE-2026-xxxx` 编号、`ACG-Faka`、`BEpusdt`、`青龙面板` 等）。
   - 去 AI 味时只洗掉标题里的营销废话后缀（如 `深度拆解`、`全解析`、`保姆级教程`、`终极版`、`底层原理与实现`），**绝对不能把核心产品名、套餐名、报错原词、CVE 编号或圈内高频俗称改丢**！
   - 正文开篇第一段内必须自然复现标题与 `tags` 里的核心检索词，确保搜索引擎摘要（Snippet）和读者第一眼视线精准命中。

2. **严禁破坏或遮蔽站点顶部的 `联系方式 & 交流群` 与 `配套服务` 导流区**
   - 本站 Hugo 模板（`layouts/_partials/article/article.html`）会自动在每篇 `posts` 正文最上方依次渲染两块全站统一的顶部引流组件：
     1) `article/components/community.html`（展示 `联系方式 & 交流群`、QQ 群 `754842541`、QQ `46333839`、微信 `GOV-HACK`）；
     2) `ads/in-article.html`（根据文章 `categories` / `tags` / `title` 自动匹配 `SwitchBase`、`RedeemAI` 或 `ZovoCard` 配套服务卡片）。
   - **关键红线**：`community.html` 内部通过 `not (strings.Contains .RawContent "/images/qq-group-qr.jpg")` 判断是否渲染统一卡片。因此**绝对禁止在文章 `.md` 正文里手动硬塞 `/images/qq-group-qr.jpg` 短代码或旧版残缺的 `> 联系方式 & 交流群` 引用块**，否则反而会把模板自动渲染的标准群号导流框顶掉；同时 Frontmatter 的 `categories` 与 `tags` 必须准确填写（如含 `Codex`、`Claude`、`AI 工具`、`支付安全` 等），让顶部配套服务卡片精准匹配业务。

## 三、微观句法、标点与代码死线

1. **绝对清零的句式与词汇黑名单**
   - **转折排比套话**：`不是……而是……`、`并非……而是……`、`不仅……更……`、`不但……而且还……`、`不在于……而在于……`、`与其说……不如说……`、`之所以……（是因为/原因）`。
   - **大模型口头禅**：`总而言之`、`综上所述`、`值得注意的是`、`需要指出的是`、`显而易见`、`不难发现`、`毫无疑问`、`众所周知`、`换句话说`、`某种意义上`、`从某种程度上`、`双刃剑`、`赋能`、`抓手`、`闭环`、`心智`、`全景`、`多维度`、`深度剖析`、`一分钟速读`、`保姆级`、`干货满满`、`家人们 / 宝子们 / 兄弟们`。
   - **标点与排版违禁品**：
     - 全文破折号 `——` 必须为 **`0` 处**（一律改用冒号 `：`、逗号 `，`、括号 `（...）` 或直接断成两句短话）；
     - 全文 `- **标题**：` 或 `1. **标题**：` 加粗冒号列表必须为 **`0` 处**；
     - 正文自然段内 `**加粗**` 总数不超过 `2` 处（优先为 **`0` 处**，重点一律用反引号 `` `...` ``）；
     - 单篇文章 Markdown 表格不超过 `2` 张，严禁空单元格，严禁把普通优缺点说明硬塞进表格；
     - 全文严禁 ASCII 字符流程图（`┌──┐`、`├──`、`──▶`）、独立成行箭头 `↓` 与任何装饰性 Emoji（`📊 🚀 💡 ✅ ❌ ⚠️ 🔥`）；
     - 全文引号风格统一（默认对齐标杆文使用英文直双引号 `"..."`，严禁同篇混用中文弯引号 `“...”` 与直双引号）；
     - 本站 Hugo 未开启数学公式扩展，美元金额直接写 `$99.99`、`$200`、`$0`，**严禁写成 `\$99.99`**（尤其在反引号 `` `...` `` 内会把反斜杠原样印在网页上）。

2. **技术零差错、零缩水与配图宁缺毋滥**
   - 所有 Python、JSON、JavaScript、Bash、TOML、Go、SQL 代码块必须语法合法、变量闭合，CLI 参数与日志路径须与上游当前真实版本核对一致；服务默认监听优先绑 `127.0.0.1` 回环口，严禁出现本机私人用户名与非官方弃用域名（本站唯一官方主域为 `caowo.de`，严禁把 `wizawn.com` 写成站长持有或曾持有域名）。
   - **配图宁缺毋滥**：实操、逆向、部署类文章没有真实过程截图时**一律留白**，绝不拿网图、AI 假界面图或代码雨凑数；原有的真实报错截图与 `.zip` / `.js` 工具附件必须完整保留并核验路径可达。

## 四、动笔前四问与标准交付流程

每次写新文章或改旧稿前，先在脑子里过一遍这四个问题，定好调子再敲键盘：
1. **这篇的搜索引流词是什么？**（标题和第一段前两句话有没有把产品名、具体报错或 CVE 号亮出来？）
2. **这篇属于哪一类题材？**（翻开 [genre-templates.md](references/genre-templates.md) 对齐对应题材的起手式与 `0x00` 推进节奏。）
3. **如果是真人亲手折腾这件事，最怕翻车或最容易卡壳的那一步在哪？**（把防呆措施、踩坑瞬间的反常现象写具体，别列干瘪的教条。）
4. **收尾停在哪最利索？**（给完最后一条实用提醒或验证命令就停笔，砍掉一切感叹和总结段。）

Frontmatter 标准模板（`google-ai-ultra-trial` 独占 `weight: 1`，其余全部原创文章统一设 `weight: 10`，排在 `weight: 100` 的 `auto-*` 资讯聚合之前）：

```yaml
---
title: "包含核心搜索词的直白标题（不挂深度拆解/保姆级等套话）"
date: 2026-11-22T20:00:00+08:00
description: "一两句大白话点明核心对象、解决的具体问题或复盘结论，自然包含引流关键词。"
categories: ["安全研究", "技术分析"]
tags: ["核心产品名", "具体协议或组件名", "报错码或CVE号"]
draft: false
weight: 10
---
```

定稿前执行静态门禁检查，必须显示 `0 issues`：

```bash
python3 ~/.gemini/config/skills/yanling-blog-style/scripts/check_ai_smell.py <目标文件或目录>
```

## 五、SEO / GEO 元数据与联系方式唯一基线

1. **联系方式唯一有效清单**
   - 站内个人与交流联系方式仅保留三项：QQ 交流群 `754842541`、个人 QQ `46333839`、微信 `GOV-HACK`。
   - **严禁写入已停用或移除的旧信息**：历史旧 QQ 群号、个人 GitHub（`github.com/wizawn`）、旧邮箱（`hihacker@foxmail.com` 等任何私人邮箱）、已下线子域名（`api.caowo.de`、`ruanzhu.caowo.de`）。
2. **SEO 与生成式搜索（GEO）元数据要求**
   - 每篇原创文章必须填写精准的 `description`（建议 45–110 字中文，直接交代研究对象、报错码/CVE 编号、协议组件与实测结论），该字段会同步喂给 `<meta name="description">`、OpenGraph、Schema.org `TechArticle` 结构化数据以及 `/llms.txt`、`/llms-full.txt` 大模型索引。
   - 修改历史文章技术内容时同步更新 `lastmod`（ISO-8601 时间戳），触发 `sitemap.xml` 与 `article:modified_time` 刷新。
   - 正式发布至 `blog-worker` 后，可执行仓库内 `python3 scripts/submit_indexnow.py` 将最新 `sitemap.xml` 主动推送至 IndexNow（加速 Bing、ChatGPT Search 与 Perplexity 收录）。
